How it works

No legacy change ships unproven.

RippleGuard maps every artifact a ticket touches. A deterministic gate — zero AI tokens — refuses the release until each ripple is proven or waived. The page below is not a diagram of the idea. It is the run.

The fear

Developers don't fear changing one line. They fear the 1998 batch job that still reads bytes 1 through 9.

CHG-1042 expands CUSTOMER_ID from CHAR(9) to CHAR(12). In a fixed-width extract every field after the key shifts three bytes. A job that still slices the old window does not throw. It bills the wrong account.

What grep cannot find

Three traps with no field name in the source.

A literal search for CUSTOMER_ID covers 12 of 15 known-impacted artifacts. The three it misses are the ones that silently corrupt production.

Trap 01 · alias

A drift-copy constant

The order service never writes the field name. It keeps a local CUSID_LEN = 9 and pads every lookup to that width. Grep for the column never lands here.

const CUSID_LEN = 9;
const key = String(custNo)
  .padEnd(CUSID_LEN, ' ')
  .slice(0, CUSID_LEN).trim();
src/orders/orderService.js · ledger SVC_ORDER_SERVICE

code-explorer hunts drift-copies and aliases (CUSID, custNo, acct). Skill: rippleguard-analyze. Persona file: .bob/agents/code-explorer.md. Tools: Read only.

Trap 02 · anonymous offsets

Bytes, not names

The 02:00 billing job slices CUSMAS and ORDMAS by raw positions. The ops runbook said those offsets were hand-maintained — and that there was no length assertion in the job.

const acct = line.substring(0, 9);
const amt  = Number(line.substring(16, 25)) / 100;
const stat = line.substring(25, 26);
batch/nightly_billing.js:30 · OPS-311

batch-explorer is the persona that finds nameless offsets. It also reads docs/ops/BILLING-RUNBOOK.md — the runbook named the job when the source did not. Skill: rippleguard-analyze.

Trap 03 · partner contract

A spec named CUST_KEY

The 3PL feed encodes the customer key as CUST_KEY, width 9, record_length 40. Updating the config without a V2 bump would shift every field partners parse.

{ "name": "CUST_KEY",
  "offset": 0,
  "width": 9,
  "pad": " " }
config/feed-layout.json · PARTNER-DAILY-V1

Same batch-explorer pass. Config and ops docs are in its search path. A grep for CUSTOMER_ID never opens a file that only says CUST_KEY.

$ grep CUSTOMER_ID → 12/15
Misses orderService.js · nightly_billing.js · feed-layout.json. RippleGuard found all three, plus the two data extracts — 17 ripples on the live run.

Phase 02 · skill rippleguard-analyze · step 2

Five personas, five isolated windows.

Analyze fans out read-only explore subagents. Each persona lives in .bob/agents/, tools: Read only. They return { path, line, quote, why, risk }. Click an agent to see what it hunts and what it found on the live run. Run 1 was 14/15. Personas were tightened. Run 2 landed 15/15 plus two data extracts — 17 ripples.

Phase 03 · skill rippleguard-implement

Change only what the ledger named.

.bob/skills/rippleguard-implement/SKILL.md is the single scope contract. The ledger is the source of truth. Out-of-scope entries stay open. Status moves open → changed → tested only after a proving test. DDL and docs may be waived with an honest reason. The skill must not edit the gate or bob_sessions/.

Phase 04 · skill rippleguard-verify · persona verifier

The verifier may only downgrade.

rippleguard-verify is adversarial. It re-derives the blast radius from the PDF with fresh explorers plus the verifier persona (.bob/agents/verifier.md). It may write only the ledger (downgrade) and artifacts/verify-report.md. It never implements. It never upgrades a status.

  • 01Re-search from scratch. Do not start from the ledger; compare after.
  • 02A “tested” artifact needs a test that exercises the new 12-character behavior end to end.
  • 03Hunt silent truncation: substring, slice, pad-and-cut, contractual widths.
  • 04Run the gate --strict and nightly_billing.js read-only. Report the verdict verbatim.
Real catch · SVC_CUSTOMER_SERVICE

Task 3 found customer service marked tested while the file was identical to the pre-change baseline. The referenced route test still used 9-character ids. Status went back to open. The gate stayed blocked — on purpose.

Phase 05 · scripts/ripple-gate.js · zero AI

Zero tokens. Exit code 1 or 0.

The rippleguard command’s last phase is not a skill. It is Node. The gate reads the ledger, diffs every path against the baseline manifest, runs the suite, and audits quotes with verify-evidence.js. Project rule: report the verdict verbatim. If it blocks, the release is blocked.
